# D3 formal Dense versus Top-1 MoE results

Date: 2026-10-07. D3 completes the single-GPU Top-1 MoE stage with a formal
no-Profiler performance comparison and a deterministic 300-update stability
comparison on TinyStories full.

## Formal benchmark protocol

Dense and MoE used the same RTX 5060 Laptop GPU, TinyStories full data, BF16,
sequence length 512, micro-batch 8, four gradient-accumulation steps, and
16,384 tokens/update. `torch.compile` and Profiler were disabled. Each variant
ran in three independent processes with 20 warmup and 100 measured updates.

All six runs used warmup-window hash
`dd63f9cea96065dbbd1382cb13f4244452ab93f63f3262e37340d1ef49acb91b`
and measurement-window hash
`b920fdb1d2364511a3673bebce3395fa739d8b25c6340cc4d544a0ea7ea91157`.
All measured LM and total losses were finite.

Run commands:

```bash
for run in run1 run2 run3; do
  uv run python train.py config/benchmark_d3_dense.py \
    --benchmark_run_id="$run"
done

for run in run1 run2 run3; do
  uv run python train.py config/benchmark_d3_moe.py \
    --benchmark_run_id="$run"
done
```

## Parameter accounting

| Variant | Total parameters | Active parameters/token | Non-position total | Non-position active/token |
|---|---:|---:|---:|---:|
| Dense | 51,168,256 | 51,168,256 | 50,906,112 | 50,906,112 |
| Top-1 MoE | 57,461,760 | 51,170,304 | 57,199,616 | 50,908,160 |

Replacing one Dense MLP with four experts adds 6,293,504 stored parameters,
but Top-1 activates only one expert. The per-token active increase is the
2,048-parameter router. “Active parameters” is a parameter-count description,
not a guarantee of equal FLOPs or equal kernel efficiency.

## Formal benchmark results

| Variant | Run medians (ms/update) | Median | Tokens/s | Peak allocated | Peak reserved |
|---|---|---:|---:|---:|---:|
| Dense | 347.281 / 347.165 / 347.190 | 347.190 ms | 47,190 | 3,907.0 MiB | 4,912.0 MiB |
| Top-1 MoE | 391.070 / 384.411 / 391.047 | 391.047 ms | 41,898 | 4,032.8 MiB | 4,962.0 MiB |

MoE achieved 88.78% of Dense throughput: tokens/s decreased 11.22% and step
time increased 12.63%. Median peak allocated/reserved memory increased by
125.8/50.0 MiB. The Dense run-median range was 0.116 ms and the MoE range was
6.659 ms.

This result is expected for the current educational implementation. Top-1
sparsity keeps expert matrix computation close to one Dense MLP per token, but
the Python expert loop, data-dependent indexing, gather/scatter, router, and
less regular expert batches add overhead. The result does not imply optimized
grouped MoE kernels are universally slower.

## 300-update stability comparison

The stability runs used the same model/data settings and deterministic seed.
Both consumed the same 9,600 training windows with hash
`89ef35fae4ae3a7a741b7bdc4c76e5420edcdfbe63be9ba8cb64e5e254a5445e`.
Each validation point averages 20 train and 20 validation batches.

```bash
uv run python train.py config/train_d3_dense_stability.py
uv run python train.py config/train_d3_moe_stability.py
uv run python scripts/summarize_d3_moe.py
```

| Update | Dense validation LM loss | MoE validation LM loss | MoE − Dense |
|---:|---:|---:|---:|
| 0 | 10.9115 | 10.9295 | +0.0180 |
| 100 | 4.1556 | 4.1463 | −0.0093 |
| 200 | 3.7642 | 3.7485 | −0.0157 |
| 300 | 3.6436 | 3.6250 | −0.0186 |

Both runs remained finite and completed without OOM. The final MoE loss is
slightly lower in this one deterministic run, but this is not a repeated
quality study and does not establish a statistically meaningful advantage.

MoE routing over all 300 updates:

- expert counts: 1,162,616 / 1,214,102 / 1,269,281 / 1,269,201;
- max/mean load: 1.033; load CV: 0.0361;
- aggregate drop rate: 1.88%; worst update drop rate: 39.59%;
- normalized load entropy: 0.9995.

Over the final 100 updates, counts were 400,577 / 379,928 / 431,698 / 426,197,
load CV was 0.0507, and no token was dropped. The high worst-update drop rate
occurred during early router adaptation; it did not persist.

## Scope and artifacts

Formal timings exclude startup, evaluation, checkpointing, routing telemetry,
and compilation. The 300-update runs include telemetry and evaluation and are
not throughput measurements. Conclusions apply to this model shape, eager
implementation, software environment, and GPU.

Raw benchmark files are under `benchmark/dense/` and `benchmark/moe/`.
`stability_dense.json` and `stability_moe.json` contain per-update/evaluation
records. `summary.json` is generated by `scripts/summarize_d3_moe.py` and
validates the benchmark and stability invariants.
