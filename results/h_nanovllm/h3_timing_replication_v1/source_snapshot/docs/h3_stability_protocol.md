# H3 v5 计时稳定性复验

2026-11-02，在新资格和正式测量前冻结。配置为
[h3_stability_v1.json](../config/serving/h3_stability_v1.json)。

本轮完成执行计划中的稳定性调查，不替换原36个进程、原三次配对诊断或任何历史失败。
模型、权重、请求数组、固定continuation、BF16 dtype、关闭中间累积降精度、Prefix off、
TP1、池大小、计算路径及run_wave计时逻辑全部沿用
[v5](h3_performance_v5_protocol.md)，不改旧源码、配置和门槛。

预选long_prefill（历史进程吞吐max/min=2.46）和batch_short（历史波内CV最高36.41%），
各比较native_kv、paged_eager、paged_graph。六轮使用六种路径排列，每条路径在每个
位置出现两次；相邻轮交替case顺序和两种计时范围的顺序。每个case/路径/轮次都使用
新独立进程，共36个。两种范围分别预热20波、测量20波，固定次数，不按观测延长、
删异常波或选择有利重跑。预热与全部测量trace均保留。

执行前独占全局GPU锁、要求GPU为0 MiB并检查交流供电；保持原电源与时钟配置。
先只读复核原v5完整2592个数值向量、864个Graph exact向量及原36进程审计。
随后用三个新进程各重建两case，毒化KV，收集新的1728个全词表BF16向量，逐元素
比较原同权重FP32数学参考；576个eager/Graph向量须bitwise exact。参考/原始大张量
重新打开、哈希复核，原atol=.125/rtol=.02/relative_RMSE<=.005保持不变。
旧资格证明与新资格同时通过，且源码/环境/模型/输入绑定一致，才能启动正式计时。

测量范围仍分开：model_execution为CUDA Event模型调用区间，可能包含提交空隙；
replay_e2e包含共同控制、H2D、argmax与CPU交接。scope分别运行，禁止交叉相除。
不含模型启动、Graph捕获、预热或传感器采集。温度、P-state、SM/显存时钟、功耗、
功率上限、CPU负载和交流供电在每个scope开始、预热后、测量每5波后留样；不在
run_wave的计时窗口内启动nvidia-smi。采样间歇及其可能的后续影响明确保留，不将
这些离散快照当成连续kernel遥测或唯一波动根因。

每个进程保留20波中位吞吐、TTFT/TPOT/ITL、wall与measurement CV、实际KV与峰值
allocated/reserved、页增长和回收、argmax/输出哈希。每格报告六个独立进程的中位数、
全部值和最小/最大范围，按轮报告配对吞吐比及CV。禁止将120波当成120个独立进程，
不将经验p99当成生产尾延迟。

预声明稳定性标准：每格全部进程的wall和measurement CV均<=15%，六进程吞吐
max/min<=1.25；对应配对吞吐比CV<=15%。是否通过完整报告，不作为删除数据或
自动重跑的准入门槛。工程验收要求数值资格、36进程完整、原始trace/指标独立重算、
源码/历史证据不变、CPU测试、导出哈希和进程/GPU清理；稳定性结果可为仍有波动。
若未达到稳定性标准，就保留不确定性，不能把“调查完成”写成“稳定性能幅度已证明”。

范围限两种既有离线case、固定token回放和本机；不是自然生成、HTTP、线上SLO、
最大容量或多卡证明。正式期间不运行其他GPU工作或CPU审计/测试。超时/失败保存
日志、journal和原目录并停止，不覆盖。无付费资源、环境升级或系统频率设置变更。
